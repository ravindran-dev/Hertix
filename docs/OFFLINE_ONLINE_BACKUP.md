# Offline and Online backup

Offline is the durable local library and audio files on the device. Account changes and incoming cloud rows no longer replace or hide offline playlists. Online uses an account-scoped cache and private cloud storage. Opening Online is distinct from restoring audio to Offline.

Recovered bgm on the connected phone from the cached cloud playlist: 46 active memberships, all mapped to existing local tracks. Original library/cache copies were preserved in the app's music/recovery directory before writing the reconstructed local playlist. Pending operations were retained. Duplicate creates already equal to the cloud are dismissed without remote writes. After local restoration, matching song order is compared independently of gaps in cloud position values; genuinely different versions still require a named review.

Backup is opt-in per account. Users choose library data, audio files, automatic/manual operation, and Wi-Fi-only or Wi-Fi/mobile networking in an explicit permission dialog. Nothing new is uploaded by default. Android notification permission is requested separately. Music upload permission covers the metadata needed to identify those files. Local JSON export remains a metadata-only offline backup and is separately labeled.

A persisted JobScheduler job runs automatic backup under allowed network constraints. Scheduling is Android-managed, not an exact timer. Manual backup can be queued from Account. Account/consent/network checks gate metadata writes and each audio upload. The worker checks hashes against server-confirmed ready objects, resumes matching pending reservations, cleans expired unconfirmed reservations on an allowed network, and checks server confirmation after upload. Transient failures retry; quota, format and size failures remain visible for user action. Jobs are bounded and retain durable server receipts/operations across interruption; local source files are never deleted. Progress appears in Account and in the backup notification when permission is granted. Pausing preserves confirmed files.

The current cloud backend accepts supported audio formats up to 25 MiB/file, with the configured account quota (initial schema default 1 GiB). It does not accept arbitrary documents/video files through this audio backup flow. Limits are shown in the permission description and errors. Source/network/server failures remain possible and are reported rather than silently described as success. The worker verifies uploaded hashes/server readiness; it does not claim to test production email delivery or all OEM background scheduling.
